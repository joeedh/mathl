# mathl

GLSL/shader-like language compiler. Parses GLSL-flavoured source into
an AST, transforms it (resolves polymorphic builtins and operators,
rewrites swizzles), and emits JavaScript you can `eval()` and call.

The codebase is mid-migration from JavaScript to TypeScript — most of
`core/`, `parser/`, `generators/`, and `tests/` are `.ts`; a few files
in `core/` and `transform/` are still `.js`. New code should be `.ts`.

## Build / test commands

- `pnpm build` — esbuild bundle into `build/`
- `pnpm watch` — esbuild in watch mode
- `pnpm typecheck` — `tsgo --noEmit` (use this, **not** `tsc`)
- `pnpm test` — jest, runs `tests/*.test.ts`
- `pnpm format` — prettier
- `pnpm eslint` — lint with cache
- `node build_parsetable.js` — rebuild `parsetable.json` after editing
  the grammar in `parser/parser.ts`

## Public API (from `index.ts`)

```ts
import * as mathl from 'mathl'

mathl.parse(src, filename?)         // → ParseState (with .ast)
mathl.preprocess(src)               // → string (after #define / comments)
mathl.genCode(ctx, 'js' | 'internal')  // → string
mathl.genJS(ctx)                    // shortcut for genCode(ctx, 'js')
mathl.compileJS(src, filename?)     // → CompiledJS (parses + compiles + eval)
mathl.silence() / mathl.unsilence() // toggle console output during parses

// from javascript_types
mathl.GLSLValueType                 // enum: float | int | bool | vec2 | ...
mathl.CompiledJS                    // interface
```

The shape of a `CompiledJS` is fully described in
`generators/javascript_types.ts` — see also `documentation/generator.md`.

## Pipeline at a glance

```
source string
  │
  ▼ preprocess()  (parser/preprocessor.ts)
expanded source
  │
  ▼ GLSLLexer + LALR(1) driver  (parser/parser.ts, parser/jscc_util.ts)
ProgramNode (raw AST)
  │
  ▼ prepend cached library AST  (core/mathl.ts::parse)
program + library AST
  │
  ▼ findSlots()    populate ParseState.inputs/outputs/uniforms
  ▼ transformAst() resolve types, dispatch poly funcs, rewrite swizzles
  │              (transform/process_ast.ts)
typed AST + ParseState
  │
  ▼ CodeGenerator.getGenerator('js').genCode()
JS source string
  │
  ▼ eval()  (in compileJS)
CompiledJS  ← drive via .uniforms / .setInput / .call / .outputs
```

Two key tricks make this work:

1. **Polymorphic dispatch**. GLSL is overloaded; JS isn't. `ParseState`
   pre-registers a `_$_<name>__<ret>__<args>` key for every builtin /
   operator overload, and `transform/process_ast.ts` rewrites call
   sites and binary-op nodes to use those keys. The implementations
   are auto-generated by `state.ts::genLibraryCode()` as a giant GLSL
   string that gets parsed once, cached, and prepended to every user
   parse. The JS generator then emits plain function calls into the
   keyed names, which the runtime prelude (`generators/javascript.ts`
   `jslib`) maps to `Math.sin`/etc. for scalar cases.

2. **Cached parse table**. The LALR(1) table is expensive to generate,
   so it's hashed-and-stored in `parsetable.json`. Editing the grammar
   in `parser/parser.ts` will make `getParser()` throw "parser is out
   of date; run build_parsetable.js" — that's the fix: rerun
   `node build_parsetable.js`.

## Library code (`state.ts::libraryCode`)

`genLibraryCode()` programmatically builds a single GLSL source string
containing:

- Vector forms of every scalar math builtin
  (`sin(vec3)`, `cos(vec4)`, `exp(vec2)`, `min`, `max`, `pow`, `step`,
  `abs`, `floor`, `ceil`, `mod`, `sqrt`, `log`, `atan`, …).
- Per-type operator overloads for `vec2`/`vec3`/`vec4` (`+`, `-`,
  `*`, `/`, `>`, `<`, `==`, `!=`, `&`, `|`, `^`, and their
  scalar-on-vector / vector-on-scalar variants).
- Constructors for every length permutation of `vec2..vec4`.
- `int_cast` / `float_cast` / `bool_cast` overloads.
- `mat4 * vec4` multiplication.

This is parsed once at startup with `getLibraryCode()` and cached in
`localStorage` under `_mathl_library_code` / `_mathl_library_hash`.
The hash is `libraryCodeVersion` (currently `9`) plus a string hash of
`libraryCode` itself, so changes to either invalidate the cache.

## ASTNode model

Every AST node extends `ASTNodeBase<VALUE, TYPE>` which itself extends
`Array<ASTNode>`. Children are array elements; `n.length` is child
count. Other useful fields:

- `n.type: string`   — `'BinOp'`, `'VarDecl'`, etc.
- `n.value`          — payload (e.g. identifier name, function name,
                        operator literal, `VarType` instance)
- `n.op`             — set on `BinOp`, `Assign`, `UnaryOp`
- `n.prec`           — operator precedence (BinOp only)
- `n.ntype: VarType` — resolved type after the type-resolution pass
- `n.polyKey`        — set by transform pass; key into the poly-func
                        registry
- `n.qualifier`      — `TypeQualifierNode` for storage/layout/precision
- `n.line`, `n.col`, `n.lexpos` — source location

Mutate via `n.push`, `n.remove`, `n.replace`, `n.insert`, `n.prepend`,
`n.set(idx, child)` — these all maintain `parent` pointers and
reparent on the way in. Don't assign children with `n[i] = ...`
directly, you'll skip the bookkeeping.

Walk via:

- `walk(ast, handlers)` — by type
- `fullVisit(ast, cb)` — every node, preorder
- `controlledVisit(ast, handlers, state)` — handlers explicitly recurse
- `scopeWalk(ast, handlers, state)` — also tracks scope (transform pass)
- `traverse<State>(ast, initial, handlers)` — typed traversal used by
  the generators

## ParseState gotchas

- `ParseState` is **stored in a module-level singleton** (`state.state`
  in `core/state.ts`). Parsing pushes a new one (`pushParseState`) and
  pops on completion. Don't keep stale references across a `parse()`
  call.
- `state.inputs` / `state.outputs` / `state.uniforms` are
  `Map<string, VarDeclNode>` and only populated *after* `findSlots()`
  runs (during `parse()`).
- Polymorphic builtins are registered in `ParseState.reset()`, which
  fires from the constructor — so a fresh `new ParseState()` already
  has every builtin known.

## Adding a generator

1. Create `generators/foo.ts`, subclass `CodeGenerator`, implement
   `static generatorDefine()` returning `{typeName: 'foo'}`, override
   `genCode(ast?)`.
2. Call `CodeGenerator.register(FooGenerator)` at module scope.
3. Add `import './foo.js'` to `generators/all.ts`.
4. Consume with `mathl.genCode(ctx, 'foo')`.

Use `generators/internal.ts` as the simplest reference and
`generators/javascript.ts` as the full-featured one. See
`documentation/generator.md` for the JS generator's output shape.

## Tests

`tests/glslToJS.test.ts` is the canonical end-to-end test — parse,
compile, set uniforms / inputs, `call()`, snapshot the outputs. The
snapshot lives under `tests/__snapshots__/`. There's also a
`localStorageEmu.test.ts` that exercises the localStorage shim used
to cache the parsed library code.

Running a single test:

```bash
npx jest tests/glslToJS.test.ts
```

`globalThis.INSIDE_JEST = true` (set by `tests/setup.js` and inside
each test file) keeps `ParseState.error` from calling `process.exit`
and instead throws — useful so jest can report failures normally.

## Common edits

- **New keyword** — add the uppercase form to the `keywords` Set near
  the top of `parser/parser.ts`, then add token rules / grammar rules
  for it, then `node build_parsetable.js`.
- **New built-in function** — add the name to `builtinFuncs` in
  `ParseState.reset()`, add `addPolyFunc(...)` calls for every overload
  set you want, and add the implementation to `genLibraryCode()` (or,
  for scalar-only ones, alias it in `jslib` like
  `_$_foo__float__float = Math.foo`).
- **New AST node** — add a class in `core/ast.ts` extending
  `ASTNodeBase<VALUE, 'YourType'>`, call `registerSubclass(...)` so
  nstructjs knows about it, add the type string to `AstTypes`.
- **Grammar change** — edit `parsedef` in `parser/parser.ts`, then
  rebuild the table.

## Files you'll rarely touch but should know exist

- `parsetable.json` — generated; commit it after running
  `build_parsetable.js`.
- `util/jscc.js`, `util/lzstring.js`, `util/nstructjs_es6.js` —
  vendored third-party code, don't edit.
- `util/parseutil.ts` — `lexer`, `token`, `tokdef` base classes
  (the GLSL lexer extends `lexer`).
- `util/localStorage.ts` — small shim so the library-code cache works
  outside browsers (in Node / jest, backs to a JSON file
  `localStorage.json`).
- `esbuilder.js`, `rollup.config.js` — build configs.
- `serv.js` — tiny dev server for `index.html`.
- `df_tests.js` — derivative / autodiff experiments.

## Quick orientation if you're new

If you need to fix something, start by finding the failing case:

- **Parse failure** → `parser/parser.ts` (grammar) or
  `parser/preprocessor.ts` (`#define` interactions).
- **Type / overload resolution failure** → `transform/process_ast.ts`
  and `core/state.ts` (`addPolyFunc`, `buildPolyKey`).
- **Generated JS doesn't run / wrong output** → `generators/javascript.ts`.
- **"unknown generator X" / nothing registers** → check
  `generators/all.ts` imports your backend and that
  `core/mathl.ts` imports `generators/all.js`.

Then re-run `pnpm test` and iterate.
